# 01 Requirements

## 用户与目标

内容团队需要从待处理素材中识别可排期项，完成审核、冲突检查和可确认的发布排期草稿。系统的交付结果必须包含：审核状态、风险原因、建议时段、待确认项和草稿保存状态。

## 输入与工具

- 输入：素材 ID、元数据、发布时间要求、已有排期、审核规则。
- 业务工具：`get_material`、`check_rules`、`check_slot`、`save_draft`。
- 用户确认：当目标时段冲突且存在替代时段时，必须暂停等待明确确认。

## 成功标准

1. 审核通过且目标时段可用时，保存一份 `draft` 草稿，并明确“尚未发布”。
2. 信息缺失时，返回 `needs_info` 和缺失字段，不保存草稿。
3. 规则风险时，返回 `blocked` 和风险原因，不保存草稿。
4. M01 请求 18:00 且已占用、19:00 可用时，建议 19:00 并等待确认；确认前不得保存或称为发布。
5. 相同业务请求重复提交时只能复用已有草稿。
6. 保存失败时必须返回 `failed`，不得伪报成功。

## 范围与非目标

- 本题实现 CLI、LangGraph、SQLite 和可选 OpenAI 兼容 LLM。
- 只保存草稿；没有真实发布工具、发布 API 或 `published` 状态。
- 不实现 HTTP API、PySide6、多租户、生产权限系统或真实内容平台接入。

## 已知限制

- 替代时段只在当前 demo 规则中按小时搜索有限候选；生产系统需要接入真实排期容量和时段策略。
- 在线模型配置缺失或请求失败时，系统明确输出 stderr 提示并降级为确定性安全 fallback。
